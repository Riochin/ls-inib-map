# `/about` LP風リデザイン 設計書

作成日: 2026-09-17
対象ブランチ: `ver2.5.3`（PRタイトルは `2.5.3`）

## 目的

`/about` を、X で初めてリンクを見た人に「何のサイトか・使うとどう良いか」が一目で伝わる LP 風のページにする。
アプリの入口は引き続き `/`（地図）であり、独立した LP は作らない。`/about` の上半分を LP、下半分を従来の説明・FAQ・免責などにする。

素材は 2026-07-11 の紹介配信スライド（`20260711 ラスサバ・イニブ 設置店舗マップ紹介配信.pdf`）を流用する。スライドはすでに「課題 → 作った → 嬉しいポイント3つ → まとめ」の LP 構成になっており、配信で一度伝わった流れを崩さない。

## 決定事項（ブレスト結果）

| 論点 | 決定 |
|---|---|
| 主な読者 | X で初めてリンクを見た人（ビジュアル重視・短い文章） |
| ヒーローでアプリを見せる方法 | 本番サイトを実際に撮影したスクリーンショット（静止画）。地図の埋め込みはしない |
| 既存内容（説明・FAQ・プライバシー・免責・開発者情報） | 全部残して下半分にまとめる。SEO・構造化データは据え置き |
| 進め方 | スライドの流れをそのままページにする。スクショは当初スライドから流用したが、レビューで「本番の実画面を撮り、スマホ枠は CSS で付ける」に変更 |

## 設計1: ページ構成（上から順）

1. **パンくず**: ホーム › このサイトについて（現状維持・小さく）
2. **ヒーロー**
   - h1: 「戦場選びをサクッと10秒に。」（ページ上の見出しをキャッチコピーにする。メタタイトルは「このサイトについて」のまま）。黒文字で「10秒」だけ紫。トップのヘルプモーダルと同じ文言・配色。改行は「戦場選びを」／「サクッと10秒に。」で固定
   - サブ文: 「ラスサバ・イニブの設置店舗を、地図でまとめて確認できる非公式サイトです」（現行の導入文を流用。正式名称は下半分の「対応タイトル」に残る）
   - 表紙の日本地図スマホ画像
   - ボタン「地図を開く」（`/` へ）
3. **課題の吹き出し**
   - 見出し「こんなときに使えます」を可視で置く（願望形の吹き出しに合わせた言い方）（「嬉しいポイント」と同じ見出しスタイル）
   - スライドの吹き出しとアプリの機能をもとに 11 個を並べる。語尾は「〜たい」で統一: 「近くで遊びたい」「遠征先で遊びたい」「大人数で集まりたい」「ペア戦か知りたい」「営業時間を知りたい」「録画したい」「配信したい」「喫煙所がある店で遊びたい」「電子マネーで払いたい」「行き方を調べたい」「店を友だちに教えたい」（場所 → 集まり方 → 営業時間・設備 → 支払い → 行き方・共有の順。アプリで応えられる困りごとだけを載せる）
   - 締めの一文は置かない（レビューで削除）
4. **嬉しいポイント3つ**（各: 番号バッジ付き見出し＋2〜3行の説明＋スクショ）
   - ① 全国◯店舗が一目でわかる（◯はデータから自動）。全国地図のスクショ
   - ② エリア・現在地・台数で／簡単に絞り込める（PC 幅のみ「〜台数で」で改行。スマホは自然に折り返す）。絞り込み画面のスクショ
   - ③ 出どころつきの情報で／安心して行ける（PC 幅のみ「〜情報で」で改行。「一目で」「簡単に」「安心して」で語調を揃える。「わかる」の重複を避ける）。公式データを自動更新し、利用者の報告を運営が確認して反映。店舗詳細のスクショ
5. **まとめ＋ボタン**: 「全国◯店舗の信頼できる情報を、サクッと探せます」＋「地図を開く」（2回目）
6. **下半分（既存内容・据え置き）**: 対応タイトル、データについて、よくある質問、エリアから探す、プライバシー、免責、開発者・お問い合わせ、フッター
   - 「このサイトでできること」の箇条書きはポイント3つと重複するため削除する

### 変えないこと

- URL `/about`、メタタイトル、ディスクリプション、canonical
- 構造化データ（BreadcrumbList・AboutPage＋著者・FAQPage）
- `/`・`/area` 配下・sitemap

## 設計2: 見た目とレイアウト

### 基本方針

- スマホ優先。縦1列で読める形を先に作り、PC幅（`md:` 以上）ではヒーローとポイント3つだけ2列にする
- 色・文字は現行サイトに合わせる。紫 `#7B2FBE` を見出しとボタンに、本文は現行 about と同じグレー。見出しフォントは about layout が読み込む丸ゴシック（M PLUS Rounded 1c 全文字版）
- 横幅は現行 about と同じ枠（`max-w-3xl`・左右余白）に収める。ダークモード非対応（現状どおり）

### ブロック別

- **ヒーロー**: スマホは「コピー → サブ文 → ボタン → 画像」の縦積み。PCは左に文章・右に画像。コピーは 2.25rem 前後・紫。背景は白のまま、画像の後ろにだけ薄い紫の丸をぼかして敷く
- **吹き出し**: 角丸チップを横に流して折り返す。色は薄い紫地・濃い紫文字で統一（レビューでグレーとの交互を廃止し、その後紫テーマに変更）。スマホは小さめ（text-sm）、PC幅は本文より一段大きく
- **ポイント3つ**: 「番号バッジ（①②③）＋見出し＋説明＋スクショ」。スマホは縦積み、PCは画像と文章を左右交互。スクショ幅は最大 250〜270px 程度
- **余白**: レビューで「全体的に余白が不十分」と指摘があったため、LP ブロック間は 4〜6rem、各ブロック内も 2〜3rem を確保する。about layout の外側余白も広げる（スマホ 1.25rem／PC 2rem）
- **まとめ**: 薄い紫の帯の中に一文とボタン
- **下半分**: 現行どおり。上半分との境目に細い区切り線

### 画像

- PDF から取り出した 4 枚（表紙の地図、全国地図、絞り込み、店舗詳細。いずれもスマホ枠込み）を `public/about/` に置く
- 幅 800px 程度に縮小し、1枚 200KB 以下を目標にする
- WebP（透過あり）に変換して置く。表示幅の2倍（ヒーロー 640px・ポイント 560px）に縮小
- 幅・高さを指定した素の `<img>` で表示する（`next/image` は使わない。`renderToStaticMarkup` の単体テストでそのまま描画でき、クライアントJSも不要なため）。ヒーロー画像は `fetchPriority="high"`、残り3枚は `loading="lazy"`。幅・高さ指定でレイアウトシフトを防ぐ
- 代替テキストは画面の内容を説明する文（例: 「地図に全国の設置店舗がピンで表示されている画面」）
- スクショの中身は撮影時点の本番データ。本文の店舗数はスクショに合わせず、従来どおりデータから自動で出す。数字が古くなったら撮影スクリプトで画像だけ撮り直す

### ボタン

- 「地図を開く」: 紫塗りつぶし・白文字・角丸。スマホでは横幅いっぱい、高さ 3rem 程度
- クライアント JS 非依存の素の `<a href="/">`（area ページと同方針）

## 設計3: 作り方・部品分け・テスト

### 部品

現行 `src/components/about/AboutContent.tsx` は1ファイルに全部入っているため、上半分を切り出す。

| 部品 | 役割 | 入力 |
|---|---|---|
| `PhoneFrame` | スクショをスマホ端末風に見せる CSS 枠（`<img>` 込み） | 画像メタ・優先読み込みフラグ |
| `AboutHero` | コピー・サブ文・ボタン・表紙画像 | なし（文言は `about-copy.ts`） |
| `AboutPainPoints` | 困りごとの吹き出し | なし（文言は `about-copy.ts`） |
| `AboutFeatures` | ポイント3つ | 店舗数（①の見出しに使う） |
| `AboutSummaryCta` | まとめの帯とボタン | 店舗数 |
| `AboutContent` | 上記を上に並べ、下半分は従来どおり | 現行と同じ props |

- 文言（コピー、吹き出し、ポイント3つの見出しと説明、まとめ文）は `src/lib/about-copy.ts` に1か所でまとめる（FAQ を `about-seo.ts` に置いているのと同じやり方）
- 各部品は同期・presentational にし、`renderToStaticMarkup` で単体テストできるようにする（既存 about/area と同方針）

### データの流れ

- 店舗数・都道府県数は現行どおり `src/app/about/page.tsx` がビルド時に集計して渡す
- 画像は `public/about/` の静的ファイルをパス指定で参照。寸法・代替テキストは `about-copy.ts` に持つ。外部取得なし

### SEO

- h1 の文言がキャッチコピーに変わる以外、メタ・canonical・構造化データは変更なし
- FAQ・免責などの本文は残るため、検索向けの文章量は減らない

### テスト

- 既存 `src/__tests__/about-content.test.tsx`（h1 が1つ、免責・プライバシー、正式名称、FAQ、店舗数、エリア導線、フッター、更新日）はそのまま通す。「このサイトでできること」削除に伴い影響するテストがあれば直す
- 追加:
  - ヒーローとまとめに `/` へのリンクが計2つある
  - 吹き出しの文がすべて出力される
  - ポイント3つの見出しが出力され、各スクショに空でない alt が付いている
  - 店舗数が本文に反映される（スクショ由来の固定数字「768」を本文に含まない）
- 仕上げ: `pnpm exec tsc --noEmit`、`pnpm lint`、`pnpm test`、`pnpm build`。ビルド後の `/about` HTML で h1 が1つであることを確認
- 見た目の確認はユーザーが自分の dev サーバーで行う（こちらでサーバーは起動しない）。必要ならユーザーがサーバーを立てた後にスマホ幅・PC幅で確認する

### やらないこと

- 別URLの追加、sitemap の変更、ダークモード対応、アニメーション
- トップページ・エリアページへの変更
- 地図の埋め込み、スクショの撮り直し
