# ADR-0002: 無制限台は「台の種類」としてゲーム別に持つ

- 日付: 2026-10-10
- ステータス: Accepted
- 関連: Issue [#31](https://github.com/Riochin/ls-inib-map/issues/31)（統合元 #402）、[画面モック](https://claude.ai/artifact/8bxiJxzwSEPmRtxZvertLy)、ADR-0003

## 背景

- 無制限台（交代なしで続けて遊べる台）の有無を知りたい要望が3名から来ている。「仲間内のカスタムマッチ用に、交代を気にせず遊べる店を探したい」という動機で、**絞り込みに使いたい**要望。ver2 の締めとして「検索系の要望ゼロ」を目標にしており、残っている検索系要望はこれだけ。
- 当初はクレジットサービス・貸切と一緒に「サービス」という1つの枠にまとめる案で進めていたが、「録画台・配信台もサービスではないか」という指摘で括りの基準が曖昧だと分かった。
- 無制限台は録画台・配信台と同じく **特定の台についている性質** で、ゲームごとに違い、数えられる。一方クレジットサービス・貸切は **店の料金や運用の決まり** で、中身が店ごとに違う。
- 設置店 770 のうち両ゲーム設置店は 230。ゲーム別に持たないと、イニブだけ無制限台がある店を正しく表せない。
- 無制限台は台数も知りたいという要望がある。

## 決定

無制限台を録画台・配信台と同じ「ゲーム別三値」で持ち、台数を任意で添える。

- 有無: `hasUnlimitedByGame`（ゲーム別 `あり / なし / 不明`。`hasRecordingByGame` と同じ型・同じマージ規則）
- 台数: `unlimitedCountByGame`（ゲーム別の数値・任意。`machineCounts` と同じ型）
- 出どころ（確定／未確認）は有無と台数で1つ（`attributeSources.hasUnlimitedByGame`）。台数だけ別に確定管理しない
- 絞り込みは「無制限台あり」（いずれかのゲームで `yes`）のみ。台数では絞らない
- 充実度スコアは録画台・配信台と同じ「台の設備」1項目に含め、項目数は増やさない
- 表示は「イニブ あり・4台（未確認）」のように有無と台数を1行で出す

理由:

- 既存パターンの複製で済む。型・オーバーライド適用・フォーム・Issue 生成・自動反映・絞り込みの各層に、録画台と同じ形で1項目足すだけ。
- 「台の性質」と「店の決まり」を分けることで、以後の項目追加の置き場所が機械的に決まる。どちらもゲーム別に持つ点は同じで、違いは置く枠と付随情報（台数か文章か）。
- 「あり・なし・不明」の三値を保つので、「この店に無制限台はない」という報告を受け取れる。配信台で「なし」の報告が価値を持っているのと同じ。

## 検討した選択肢

### 案B: 無制限台・クレジットサービス・貸切を「サービス」として1つの枠にまとめる

- 概要: 新設の「サービス」セクションに3項目を並べ、すべてゲーム別三値で持つ。
- 利点: 1つのセクション追加で #31 と #35 を同時に消化できる。
- 欠点 / リスク: 台の性質と店の決まりが混在し、「録画台もサービスでは」という境界の揺れが残る。無制限台に添える「台数」と、クレジットサービス・貸切に添える「内容の文章」という性質の違う付随情報が同じ枠に並ぶ。
- 却下理由: 括りの基準を説明できない。付随情報の形が違うものを同じ枠に置くと、表示もフォームも例外だらけになる。

### 案C: 台数だけ持つ（0 を「なし」とみなす）

- 概要: `unlimitedCountByGame` のみ持ち、三値を省く。
- 利点: フィールドが1つ減る。
- 欠点 / リスク: 「あるが台数は分からない」を表せない。報告者は台数まで数えていないことが多い。
- 却下理由: 三値の「なし」報告の価値を失う。有無と台数を分けたほうが入力の負担も小さい。

### 案D: 絞り込みに台数条件（N台以上）も入れる

- 概要: 最低台数と同じ形で「無制限台 2台以上」などを選べるようにする。
- 利点: カスタムマッチの人数に合わせて探せる。
- 欠点 / リスク: データがまだ無い段階で条件を細かくすると、該当店ゼロの絞り込みになりやすい。
- 却下理由: 要望の本質は「あるかどうか」。台数が十分集まってから検討する。

## 影響

- 楽になる: 実装は録画台の追加と同じ手順をなぞればよい。報告の自動反映ワークフローも指示文に項目名を足すだけ。
- 難しくなる: 無制限台だけ台数を持ち、録画台・配信台は持たないという非対称が生まれる。録画台の台数要望が来たら同じ形で足す。
- 見直しの目安: 無制限台の報告が 50 件を超えたら、台数での絞り込み（案D）を再検討する。
