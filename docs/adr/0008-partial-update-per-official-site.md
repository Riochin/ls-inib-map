# ADR-0008: 公式サイトの片方が取れなくても、取れたサイトの分だけで店舗データを更新する

- 日付: 2026-11-17（同日中に「件数もサイト別に見る」から「件数は都道府県単位で合算して見る」へ改訂。未マージのため新 ADR ではなくその場で改訂）
- ステータス: Accepted
- 関連: Issue #514、[実装計画](../plans/2026-11-17-per-site-partial-scrape.md)、`scripts/scrape.ts`、`scripts/merge.ts`、`.github/workflows/update-stores.yml`

## 背景

- 週次の「設置店舗データ自動更新」が 2026-10-28・11-04・11-11 の3回続けて失敗した。最後に成功したのは 10-21。
- 3回とも、イニブ公式（gundam-vs.jp）への48リクエストがすべて HTTP 403 だった。ラスサバ公式（bandainamco-am.co.jp）は全件取れていた。手元から同じ URL を同じ User-Agent で開くと 200 が返るので、サイトが止まっているのではなく、GitHub Actions のランナーからのアクセスが弾かれていると見られる。
- これまでは成否を **都道府県単位** で判定していた。1つの都道府県でどちらかのサイトが失敗すると、その都道府県を丸ごと「取れなかった」扱いにする。イニブが全滅したことで47都道府県すべてが外れ、全国0件（前回971件）になり、急減チェックで止まっていた。
- その結果、ラスサバの店舗情報も3週間更新されていない。

## 決定

取得の成否を **サイト×都道府県単位** で見て、取れたサイトの分だけで更新する。

- 件数のチェック（0件・前回比の急減）は都道府県単位のまま行い、その都道府県で取れたサイトの件数を合算して、同じサイトの前回件数と比べる。両サイトとも取れた週はこれまでと同じ判定になる。サイトごとに件数を見ると、イニブの最後の1店が消えた県（1→0件）を「不確定」として扱い続け、いつまでも掲載終了にできないため
- 掲載が消えたかどうかは、そのゲームのサイトが正常に取れた都道府県でだけ判定する。取れなかったサイトのゲーム・台数・掲載状態は前回のまま残す
- 全国の急減チェックはサイトごとに行う。急減したサイトは今回の更新から外す。すべてのサイトが外れたときだけ、これまでどおり中断して失敗にする
- サイトを外した週は失敗にはせず、「🟡 一部サイトを取得できず」という Issue で知らせる。更新 PR の本文にも書く

理由:

- 片方のサイトの障害やアクセス拒否で、もう片方の更新まで止まらない
- 外したサイトの分は前回値のままなので、誤って一斉に「掲載終了」にすることはない（データを壊さない、という元の方針は変わらない）
- Issue が出るので、取れない状態が続いていることに気づける

## 検討した選択肢

### 案B: プロキシや自前のランナーを使って 403 を避ける

- 概要: GitHub Actions 以外の IP からイニブ公式にアクセスする
- 利点: 両サイトとも従来どおり取れる
- 欠点 / リスク: 有料の経路や常時動くマシンが要る。相手が意図して弾いているなら、それを避けて取りに行くのは好ましくない
- 却下理由: 1人で運用するには重い。片方だけでも更新を続けるほうが先に必要で、根本対応は様子を見てから別途判断する

### 案C: 今の仕組みのまま、手元から手動で実行する

- 概要: 手元からはイニブも取れるので、本人が手元でパイプラインを回して PR を出す
- 利点: コードを変えなくてよい
- 欠点 / リスク: 毎週の手作業になる。ジオコーディング API キーを手元に置く必要がある
- 却下理由: 自動更新の意味がなくなる。片方のサイトが落ちるたびに同じ手作業が要る

## 影響

- 楽になる: 片方の公式サイトが取れなくても、もう片方の店舗情報は毎週更新される
- 難しくなる: 1つの店舗の中で、ゲームごとに情報の新しさが違うことがある（ラスサバは今週、イニブは前回のまま）。成否の判定とマージの条件分岐が増える
- 見直しの目安: 🟡 Issue が1か月以上続く場合は、案B の根本対応か、取得元の変更を考える
