# ADR-0004: 提供フォームの折りたたみ対象は記入率で選ぶ

- 日付: 2026-10-10
- ステータス: Accepted
- 関連: [画面モック](https://claude.ai/artifact/8bxiJxzwSEPmRtxZvertLy)、ADR-0002、ADR-0003、`src/components/StoreInfoForm.tsx`、`src/components/AddressFilterModal.tsx`（アコーディオンの既存実装）

## 背景

- 情報提供フォームは台数・営業時間・フロア・喫煙所・決済（10個のチェック）・録画台・配信台・修正通報・SNS ID と項目が多く、ver2.6 で無制限台・クレジットサービス・貸切が加わる。
- 「細かい情報は折りたたんでよいのでは」という方針が出た。直感では録画台・配信台・無制限台のような細かい項目をたたむ案になりやすい。
- 過去の「ユーザー報告」Issue 184 件で、項目ごとの記入率を数えた。

| 項目 | 記入率 |
|---|---|
| 配信台 | 81% |
| 録画台 | 79% |
| 喫煙所 | 63% |
| フロア | 59% |
| 営業時間 | 54% |
| 台数 | 23〜33% |
| 決済・電子マネー | 12% |

- 1件あたりの記入項目は平均 4.8。無制限台はまだデータがゼロで、絞り込みを成立させるには報告を集める必要がある。

## 決定

折りたたむ対象を **「細かそうな項目」ではなく「実際に書かれていない項目」** で選ぶ。

- たたむ: 決済・電子マネー、店のサービス（クレジットサービス・貸切）
- 開いたまま: 台数、営業時間、フロア、喫煙所、録画台、配信台、無制限台
- 決済は無制限台の下へ移し、たたむ項目を下にまとめる
- たたんだ見出しの右に中身の要約（「未入力」「3件選択」「クレジットサービス あり」）と「登録済み」を出す
- 見た目と操作は絞り込み画面のアコーディオン（`renderAccordionHeader`）にそろえる
- 初期状態は閉じる。開閉状態は保存しない（報告は1回きりの操作）

理由:

- 録画台・配信台は最も書かれる項目で、たたむと報告が減る。無制限台をその並びに置けば同じように書いてもらえる見込みがある。
- 決済はフォームで最も場所を取るのに記入率 12%。ここをたためば項目を足しても今より短くなる。
- アプリ内にすでにある操作なので、利用者に新しい UI を覚えさせない。

## 検討した選択肢

### 案B: 細かい項目（録画台・配信台・無制限台）をたたむ

- 概要: 基本情報だけ開き、台の設備は「詳しい情報」としてたたむ。
- 利点: 初見のフォームが短く見える。
- 欠点 / リスク: 記入率 80% の項目を隠す。無制限台のデータ収集が遅れ、絞り込みが機能しない期間が延びる。
- 却下理由: 実データと逆の判断になる。

### 案C: たたまず全部並べる

- 概要: 今の形のまま項目を足す。
- 利点: 実装が最小。見落としが無い。
- 欠点 / リスク: 決済の10チェックに加えて3項目増え、送信ボタンまでが遠くなる。
- 却下理由: 項目追加が続く見込みで、長さの問題は今後も悪化する。

## 影響

- 楽になる: 今後項目を足すとき「記入率が低ければたたむ」と機械的に決められる。
- 難しくなる: たたんだ決済の記入率はさらに下がる可能性がある。12% の項目なので許容する。
- 見直しの目安: ver2.6 リリース後に同じ集計を行い、たたんだ項目の記入率が半分以下になっていたら見出しの文言や初期開閉を見直す。無制限台の記入率が録画台より大きく低ければ配置を見直す。
