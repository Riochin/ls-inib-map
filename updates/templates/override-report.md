# 台数オーバーライド 反映報告 投稿テンプレ（X）

情報提供で `overrides.json` に台数を反映したとき、提供者へのお礼＋反映内容を報告する投稿の定型。
リリース告知（`templates/announcement.md`）とは別物で、随時（提供が溜まったら）出す軽い投稿。
タグは `#ラストサバイニブ` 中心（ゲーム別タグは内容に応じて）。URLは `🔗 lsib.world`（載せる場合）。

## 型（コピー用）

2ツリー構成。**親ポストは事務的に台数だけ**、**お礼＋メンションはぶら下げリプ**に分ける。
こうすると本投稿がスッキリし、メンションで提供者に通知が届く。

親ポスト:
```
【台数情報修正】

下記の台数を修正しました。

・［店舗名］：［ラスサバ/イニブ］［n］台
・［店舗名］：［ラスサバ/イニブ］［n］台

#ラストサバイニブ
```

ぶら下げリプ（お礼＋まとめてメンション）:
```
情報提供ありがとうございました🙏 変化があればまたお知らせください。
@xxx @yyy @zzz
```

※修正告知にはサイトURLは載せない（リリース告知と違い導線目的ではないため）。

## 書き方ルール

- **店舗名・台数は overrides.json と stores.json から起こす**。店舗名は ID から解決（`stores.json` の `name`）。`machineCounts` の値、`note` の提供者名を使う。
- `source: "admin"`（運営が現地/提供で確認）ぶんが「はっきり表示（確定）」。`official`/`user-report`/`auto-scrape` は未確認＝薄バッジ（[[provenance-override-layer]]）。
- 親ポストは店舗・台数のみ（提供者名は出さない）。お礼とメンションはぶら下げリプに集約する。
- メンションは**公開の場（リプ・引用等）で情報をくれた人**に限る＝@ユーザー名で通知が届く形が望ましい。**DM等の個人的なやりとりで得た情報は無断で名前を出さない**（伏せたまま、リプのお礼文だけでまとめて謝意を示す）。表記・ハンドルは overrides の `note` や実際のやりとりを尊重。
- 件数が多い回は全部書かず「ほか○件」でまとめてOK。画像（地図スクショ等）添付は任意。
- ノンテック層前提でやさしい言葉・アイコン控えめ（[[ui-audience-nontech]]）。

## 反映の手順（投稿前）

1. 提供情報を `src/data/overrides.json` に追記（ID・`source: admin`・`note: ○○さんより提供`・`machineCounts`）
2. `pnpm test` でローダ整合（[[provenance-override-layer]] 関連テスト）を確認
3. 本ファイルの型で報告文を作り、提供者にお礼を添えて投稿
