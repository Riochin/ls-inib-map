# 実装計画

> 並行可能なタスクには番号直後に `(P)` を付与する。`(P)` は「タスク1完了後、別ファイルを読み取り専用で参照するため同時進行できる」ことを示す。

- [x] 1. 基盤ロジック（都道府県スラッグ・エリア集計）
- [x] 1.1 都道府県の正式名とローマ字スラッグの双方向対応を実装する
  - 47都道府県の正式名 → ローマ字スラッグ（ヘボン式・小文字、`-` 不使用。例「東京都」⇔「tokyo」）の対応表を定義する
  - スラッグ→正式名、正式名→スラッグの双方向変換を提供し、未知の値には `null` を返す
  - 既存の都道府県正式名配列（`PREFECTURES`）と1対1で対応させる
  - _Requirements: 1.1_

- [x] 1.2 スラッグ対応表の整合性を検証する
  - 対応表のキー集合が既存の都道府県配列と完全一致することを確認する
  - スラッグの重複が無いことを確認する
  - 双方向変換が往復で元の値に戻ることを確認する
  - 対応の無い都道府県が出現した場合にビルド時テストで失敗させる
  - _Requirements: 1.1_

- [x] 1.3 店舗データからエリア（都道府県）単位の集計ロジックを実装する
  - 店舗が1件以上ある都道府県のサマリ（都道府県名・スラッグ・営業中店舗数・タイトル別件数）を都道府県名昇順で返す
  - 指定スラッグの県詳細（タイトル別の営業中店舗一覧）を返し、該当無し（店舗0・未知スラッグ）は `null` を返す
  - 閉店（`closed`）・移設可能性（`delisted`）の店舗、および住所から都道府県が取れない店舗を除外する
  - 複数タイトルを稼働する店舗は各タイトルのセクション双方に計上する
  - 店名を日本語ロケールで昇順ソートする
  - 既存店舗データ（`stores` / `storesMeta`）のみを入力とし、新規の手作業データを要しない
  - _Requirements: 1.3, 1.6, 2.2, 6.2_

- [x] 1.4 エリア集計ロジックを検証する
  - `closed` / `delisted` / 都道府県不明の店舗が除外されることを確認する
  - 複数タイトル店が両セクションに計上されることを確認する
  - タイトル別件数と一覧の実件数が一致することを確認する
  - 都道府県名順・店名順のソート結果を確認する
  - _Requirements: 1.3, 1.6_

- [x] 2. 都道府県エリアページ `/area/[pref]` を生成する
- [x] 2.1 県ページ本体を静的生成（SSG）で構築する
  - 店舗が1件以上ある全都道府県のスラッグを静的パラメータとして列挙し、固定 URL の静的ページを生成する
  - 該当スラッグが無い場合は 404（`notFound`）を返す
  - ページ先頭に「○○県のラスサバ・イニブ 設置店舗一覧」を意味する単一の `<h1>` を可視テキストで出力する
  - 県内店舗数・データ出典・データ最終更新日（`storesMeta.lastUpdated`、欠落時は省略）を可視テキストで表示する
  - 初期 HTML に本文を含め、リクエスト時のクライアント JS 実行に依存しない
  - _Requirements: 1.1, 1.2, 1.8, 7.1_

- [x] 2.2 タイトル別セクションと店舗一覧を表示する
  - ページ内を、件数が1以上のタイトル（イニブ／ラスサバ）の `<h2>` セクションに分割する
  - 各セクションに該当タイトルを稼働する県内店舗を一覧表示する
  - 各店舗の店名・住所・ゲーム別台数（公表値があるもののみ）を可視テキストで表示する
  - 各店舗行を、既存アプリの店舗フォーカス URL（`/?store=<id>`）への巡回可能な内部リンクにする
  - _Requirements: 1.3, 1.4, 1.5_

- [x] 2.3 ページ間回遊の内部リンクを設置する
  - 地図アプリ（`/`）で当該県を見る導線を表示する
  - 近隣（または全）都道府県エリアページへの内部リンクを表示する
  - _Requirements: 1.7_

- [x] 2.4 県ページのメタデータと構造化データを出力する
  - タイトル「○○県のラスサバ・イニブ 設置店舗一覧」、県名と件数を含む description、自ページの canonical を設定する
  - BreadcrumbList の構造化データ（ホーム → 設置店舗 → ○○県）を出力する
  - 店舗一覧を表す ItemList の構造化データを出力する
  - 個別店舗を LocalBusiness としてマークアップしない
  - _Requirements: 5.1, 5.2, 5.3_

- [x] 2.5 既存デザイン言語を踏襲する
  - ブランド紫（`#7B2FBE`）、見出しフォント（M PLUS Rounded 1c）、カードの角丸・余白トーンを県ページとハブページに適用する
  - _Requirements: 6.1_

- [ ] 3. (P) エリア一覧ハブページ `/area` を生成する
  - 店舗が1件以上ある都道府県エリアページへのリンク集を可視テキストで出力する（各リンクに設置店舗数を併記）
  - サイト全体の概況（総店舗数など）を示す単一の `<h1>` を出力する
  - 自ページの canonical を設定し、静的生成（SSG）する
  - タスク1完了後に着手可能。県ページ（タスク2）・サイトマップ（タスク4）と別ファイルで並行可能
  - _Requirements: 2.1, 2.2, 2.3_

- [ ] 4. (P) サイトマップ・クロール経路に新設ページを反映する
  - サイトマップに `/area`（ハブ）と全 `/area/[pref]`（各県ページ）の URL を含める
  - 各 URL に最終更新日（`storesMeta.lastUpdated` 由来）を付与する
  - robots 設定が新設ページのクロールを許可していることを確認する（既存の許可方針を維持）
  - サイトマップが `/area` と全県 URL を含み、件数がエリア集計の都道府県数と一致することを検証する
  - タスク1完了後に着手可能。県ページ（タスク2）・ハブ（タスク3）と別ファイルで並行可能
  - _Requirements: 4.1, 4.2, 4.3_

- [ ] 5. トップページの隠し店舗リストを撤去する
  - `SeoContent` から全店舗（都道府県別リスト）の `sr-only` 出力を撤去し、文書構造のための単一の `<h1>` のみ保持する
  - 既存の title / description / WebApplication JSON-LD を維持し、ブランド検索の評価を後退させない
  - 地図アプリ（`/`）の視覚的な見た目と既存 UX を変更しない
  - 新ページ（タスク2・3・4）が揃った後に実施する（先に受け皿を用意してから隠しリストを外す）
  - _Requirements: 3.1, 3.2, 3.3, 3.4_

- [ ] 6. 既存機能への影響ゼロと自動反映を検証する
  - 既存の地図・フィルタ・検索・クラスタ機能のテストが緑のまま（影響ゼロ）であることを確認する
  - ランタイムでの店舗データ書き込みが発生せず、静的データ方針が維持されていることを確認する
  - 店舗データ（オーバーライド反映を含む）更新時に、次回ビルドでエリアページ・ハブ・サイトマップへ内容が自動反映されることを確認する
  - _Requirements: 6.3, 7.2, 7.3_
